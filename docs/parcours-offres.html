Parcours d'affichage des offres

Cette page décrit le chemin suivi par une offre depuis le composant React jusqu'à la base SQLite, puis son retour vers l'interface.

Parcours complet

1. OffersPage
frontend/src/pages/OffersPage.tsx appelle le hook useOffers et transmet les offres à OfferTable.
↓
2. Hook React
frontend/src/hooks/useOffers.ts déclenche le chargement avec un effet React, gère le chargement, les erreurs et les sessions expirées.
↓
3. Service frontend
frontend/src/services/offers.service.ts exécute GET /api/offers, ajoute le jeton d'authentification et valide la réponse JSON.
↓
4. Proxy Vite
frontend/vite.config.ts transmet /api/offers au backend sous la forme /offers.
↓
5. Authentification et autorisation
backend/src/app.ts branche la route protégée. Les middlewares vérifient le jeton et le droit de consulter les offres.
↓
6. Contrôleur
backend/src/controllers/offers.controller.ts appelle le service et transforme chaque résultat en DTO HTTP.
↓
7. Service métier
backend/src/services/offers.service.ts applique la visibilité selon le profil : toutes les offres pour l'administrateur, les offres publiées pour l'étudiant, et les offres déposées par le contact.
↓
8. Repository SQL
backend/src/repositories/offers.repository.ts exécute la requête SQLite et joint les tables companies, academic_years et periods.
↓
9. Base de données
backend/src/db/migrations/001_initial.sql définit les tables offers et periods. Une offre possède déjà un period_id.
↓
10. Retour vers React
Le mapper convertit les données SQL en DTO, puis OfferTable affiche les résultats.

Ajout d'un filtre par période

Le schéma actuel contient déjà les périodes. Il faudrait donc principalement ajouter un paramètre de requête, par exemple : GET /offers?period=P1.

Backend

  • backend/src/controllers/offers.controller.ts : lire et valider le paramètre.
  • backend/src/services/offers.service.ts : conserver les règles de visibilité et transmettre le filtre.
  • backend/src/repositories/offers.repository.ts : ajouter la période à la requête SQL.
  • backend/tests/offers.test.ts : tester les résultats filtrés et les erreurs de validation.
  • backend/API.md : documenter le nouveau paramètre.
  • backend/http/offers.http : ajouter une requête REST de vérification.

Frontend

  • frontend/src/pages/OffersPage.tsx : ajouter le contrôle de sélection.
  • frontend/src/hooks/useOffers.ts : recharger les offres lorsque la période change.
  • frontend/src/services/offers.service.ts : envoyer ?period=P1.
  • frontend/tests/OffersPage.test.tsx : vérifier le contrôle et l'appel filtré.
Aucune nouvelle migration SQL ne semble nécessaire, car les périodes et la relation entre une offre et une période existent déjà.
